Документація: встановлення man-сторінок для `sysupdate` та `up`

## 1. Опис скриптів

### **sysupdate**

`sysupdate` — це Fish-функція для інтерактивного оновлення системи на базі DNF (Fedora, RHEL, CentOS).
Вона:

* очищає кеш DNF (`dnf clean all`);
* перевіряє оновлення (`dnf check-update`);
* пропонує встановити всі пакети;
* веде лог у `$HOME/system_update_YYYY-MM-DD_HH-MM-SS.log`;
* після завершення запитує, чи потрібно перезавантажити систему.

---

### **up**

`up` — коротка команда (обгортка), що просто викликає `sysupdate`.
Призначена для швидкого запуску оновлення без набору довгої команди.

---

## 2. Man-сторінки

Для кожного скрипта є окремий man-файл:

* `sysupdate.1`
* `up.1`

Ці файли відповідають першому розділу man-довідок (користувацькі команди).

---

## 3. Вміст файлів

### `sysupdate.1`

```
.TH SYSUPDATE 1 "Жовтень 2025" "1.0" "Користувацькі команди Fish"
.SH НАЗВА
sysupdate — інтерактивне оновлення системи DNF з логуванням і запитом на перезавантаження

.SH ОПИС
\fBsysupdate\fR — це скрипт для Fish shell, який автоматизує процес системного оновлення
у дистрибутивах на базі Fedora, RHEL або CentOS.
Він виконує очищення кешу DNF, перевірку оновлень, встановлення всіх доступних пакетів,
веде лог подій та пропонує перезавантажити систему після успішного оновлення.

.SH ДІЇ
1. Очищає кеш DNF:
    sudo dnf clean all
2. Перевіряє наявність оновлень:
    sudo dnf check-update
3. Пропонує встановити оновлення:
    Бажаєш встановити всі оновлення зараз? (y/N)
4. Пропонує перезавантаження після оновлення:
    Перезавантажити систему зараз? (y/N)
5. Зберігає лог:
    $HOME/system_update_YYYY-MM-DD_HH-MM-SS.log

.SH ВИКОРИСТАННЯ
.RS
sysupdate
.RE

.SH ПРИКЛАД
.RS
sysupdate
.RE

.SH ВИХІДНІ КОДИ
0 — виконано успішно  
≠0 — помилка DNF або скасування користувачем

.SH ФАЙЛИ
$HOME/system_update_*.log — журнал оновлень

.SH АВТОР
Fish-ентузіаст.  
\fBhttps://fishshell.com\fR

.SH ДИВІТЬСЯ ТАКОЖ
\fBup\fR(1)
```

---

### `up.1`

.TH UP 1 "Жовтень 2025" "1.0" "Користувацькі команди Fish"

up — коротка команда для запуску системного оновлення через sysupdate

Вона запускає системне оновлення з усіма тими самими можливостями:
перевіркою, логуванням, установленням оновлень і запитом на перезавантаження.

## 4. Встановлення man-сторінок у систему

### ВАРІАНТ 1 — **Для поточного користувача (рекомендовано):**

1. Створи директорію:

   ```bash
   mkdir -p ~/.local/share/man/man1
   ```

2. Скопіюй файли:

   ```bash
   cp sysupdate.1 up.1 ~/.local/share/man/man1/
   ```

3. Задай права доступу:

   ```bash
   chmod 644 ~/.local/share/man/man1/sysupdate.1 ~/.local/share/man/man1/up.1
   ```

4. Онови базу `man`:

   ```bash
   mandb ~/.local/share/man
   ```

5. Перевір:

   ```bash
   man sysupdate
   man up
   ```

---

### ВАРІАНТ 2 — **Системна установка (для всіх користувачів):**

1. Скопіюй файли з правами адміністратора:

   ```bash
   sudo cp sysupdate.1 up.1 /usr/local/share/man/man1/
   ```

2. Встанови права root і дозвіл на читання:

   ```bash
   sudo chown root:root /usr/local/share/man/man1/sysupdate.1 /usr/local/share/man/man1/up.1
   sudo chmod 644 /usr/local/share/man/man1/sysupdate.1 /usr/local/share/man/man1/up.1
   ```

3. Онови кеш:

   ```bash
   sudo mandb
   ```

4. Перевір роботу:

   ```bash
   man sysupdate
   man up
   ```

---

## 5. Якщо `man` не знаходить файли

Іноді `~/.local/share/man` не входить у змінну середовища `MANPATH`.
Перевір її:

```bash
manpath
```

Якщо у виводі немає `~/.local/share/man`, додай цей шлях вручну.

Для **Fish shell**:

```fish
set -x MANPATH $HOME/.local/share/man $MANPATH
```

Додай цей рядок у:

```
~/.config/fish/config.fish
```

Потім перезапусти сесію:

```fish
exec fish
```

---

## 6. Перевірка роботи

Після встановлення перевір:

```bash
man sysupdate
```

та

```bash
man up
```

Відкриються твої власні сторінки з описом скриптів.

---

## Порада

Щоб бачити, які саме файли `man` читає, можна скористатись:

```bash
man -d sysupdate
```

Це покаже шляхи пошуку і дасть змогу переконатися, що `~/.local/share/man` дійсно використовується.
